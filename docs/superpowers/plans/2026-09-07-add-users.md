# CBRE Add User Implementation Plan

**Goal:** Let CBRE admins create accounts from the dashboard and choose admin access with a checkbox.

**Architecture:** Persist `User.isAdmin` with a false default. Authenticate every user-creation request and read the role from the database. Extend the existing dashboard with an admin-only button and accessible form. Build in a separate directory inside `/var/www/cbre` before replacing the live CBRE files.

**Constraints:** Preserve current CBRE accounts, passwords, inspections, `/cbre` routing and all other server projects. Promote only the existing `admin@zetahub.co.uk` bootstrap account. Do not provide public registration or role editing.

- [ ] Add schema field and additive SQL migration, return role from login/current-user endpoints, seed new bootstrap accounts as admins.
- [ ] Add authenticated admin-only `POST /api/users` accepting firstName, email, password and boolean isAdmin; hash passwords, default to non-admin, reject invalid or duplicate accounts without changing existing users.
- [ ] Test unauthorized/non-admin rejection, current database role enforcement, both role choices, normalization, duplicate handling, validation, and password hashing/response privacy.
- [ ] Implement dashboard top-right Add User button and accessible modal, loading/errors/success feedback, mobile layout and unchecked Admin default.
- [ ] Stage project, run tests and production build, back up CBRE source/build/database, migrate only its database and promote the requested admin.
- [ ] Publish staged build and restart only CBRE services. Browser-check the admin form, both account roles using temporary test accounts, and ordinary-user restrictions; remove only the temporary accounts created for verification.
- [ ] Confirm the existing route fingerprints remain unchanged and document deployment.
